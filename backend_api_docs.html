1. Project Overview

TutorBhaiya is an online learning platform built with Django 5 and Django REST Framework (DRF) 3.15. The backend exposes a RESTful JSON API consumed by static HTML/JS frontend pages. Authentication supports both Token-based (for API calls) and Session-based (for browser-based flows).

Base URL: All API endpoints are prefixed with http://localhost:8000/api/. Defined in tutorbhaiya/urls.py as path('api/', include('api.urls')).

2. Authentication APIs
GET /api/csrf/ Public

Function: get_csrf_token(request)

Returns a CSRF token the frontend must include in all unsafe HTTP requests. Generated via Django's get_token(). Open to everyone — no login required. Response: { "csrfToken": "..." }

POST /api/auth/register/ Public

View Class: RegisterView

Creates a new user account using UserRegistrationSerializer. Validates password strength and email uniqueness. Splits full_name into first/last name. Auto-generates a unique username from the email prefix. Auto-logs the user in and creates a DRF auth token on success.

Request FieldRequiredDescription
full_nameYesFull name — split into first/last name
emailYesUnique email, used as login identifier
passwordYesMust pass Django password validators
phoneOptionalPhone number string
Response FieldDescription
messageSuccess text
userFull user profile (UserProfileSerializer)
tokenAuth token for subsequent API calls
POST /api/auth/login/ Public

View Class: LoginView

Authenticates an existing user. Looks up the user by email first (since Django's authenticate() normally uses username), then passes credentials to authenticate(). On success, creates/retrieves a DRF token and starts a Django session.

Request FieldRequiredDescription
emailYesRegistered email address
passwordYesAccount password
Error cases: Returns HTTP 401 if email not found, or if password is incorrect (separate error messages for each).
POST /api/auth/logout/ Auth Required

View Class: LogoutView

Terminates the current Django session by calling logout(request). The client should also discard the locally stored auth token after calling this endpoint.

GET | PATCH /api/auth/me/ Auth Required

View Class: MeView

GET — Returns the current user's profile via UserProfileSerializer. If not authenticated, returns { "authenticated": false } with HTTP 401.

PATCH — Updates editable profile fields using UserUpdateSerializer in partial mode, so only changed fields need to be provided.

PATCH-able FieldDescription
first_nameFirst name
last_nameLast name
phonePhone number
bioBiography text
profile_pictureImage file upload

3. Course APIs
GET /api/categories/ Public

View Class: CategoryListView

Returns a flat list of all course categories. Each category includes its name, slug, icon, description, and a computed course_count (active courses only). Used to populate the filter tabs on the Courses page.

GET /api/courses/ Public

View Class: CourseListView — Method: get_queryset()

Returns all active courses as lightweight listing cards. Supports three query filters. For authenticated users, each course includes an is_enrolled boolean annotated via a database subquery.

Query ParamExampleEffect
?category=slug?category=sscFilter by category slug
?featured=true?featured=trueReturn only featured courses
?search=term?search=mathSearch on title or instructor name (case-insensitive)
GET /api/courses/<slug>/ Public

View Class: CourseDetailView

Returns full details of a single course identified by its URL slug. Uses CourseDetailSerializer which adds: description, created_at, outline (JSON array), roadmap (JSON array), assignments_count, exams_count, quizzes_count. Annotates is_enrolled for authenticated users.

GET /api/courses/<id>/player/ Auth Required

View Class: CoursePlayerView — Method: get(request, pk)

Returns the full course player payload — course details with all nested modules, videos, resources, and assignments. Also returns the user's progress percentage and the list of completed video IDs. Requires an active enrollment; returns HTTP 403 if not enrolled.

Response FieldDescription
courseFull course with nested modules and videos (CoursePlayerSerializer)
progressInteger 0–100 representing completion percentage
completed_video_idsArray of video IDs already watched by this student

4. Enrollment APIs
GET | POST /api/enrollments/ Auth Required

View Class: EnrollmentListCreateView

GET — Lists all courses the current user is enrolled in. Each enrollment includes nested course info, progress %, completion status, and timestamps. Results are scoped to the logged-in user only.

POST — Enrolls the user in a course. Uses get_or_create so duplicate enrollments are safely ignored (idempotent).

POST FieldRequiredDescription
course_idYesPrimary key of the course to enroll in
GET | PATCH /api/enrollments/<id>/ Auth Required

View Class: EnrollmentDetailView

Retrieve or update a single enrollment record. The queryset is filtered to the current user, ensuring users cannot access other users' enrollments. PATCH allows manually updating the progress field.

POST /api/enrollments/complete-video/ Auth Required

View Class: MarkVideoCompleteView — Method: post(request)

Marks a specific video as watched in the student's enrollment. After adding the video to completed_videos (ManyToMany), recalculates and saves the enrollment's progress percentage using the formula below. If progress reaches 100%, sets is_completed = True.

completed videos
÷
total videos in course
×
100 = progress %
Request FieldRequiredDescription
course_idYesID of the course
video_idYesID of the video to mark complete

5. Assignment APIs
GET | POST /api/assignments/<id>/submit/ Auth Required

View Class: SubmitAssignmentView

GET — Checks whether the student has already submitted this assignment. Returns full submission details (text, file URL, timestamp, marks, teacher feedback) if submitted; otherwise returns { "submitted": false }.

POST — Submits the assignment. Accepts plain text, a file upload, or both. Uses get_or_create so re-submitting updates the existing record instead of creating a duplicate. Returns HTTP 201 on first submit, 200 on update.

POST FieldRequiredDescription
submission_textAt least one requiredWritten answer text
submission_fileAt least one requiredFile upload (multipart/form-data)
GET Response FieldDescription
submittedBoolean — true if already submitted
submission_textWritten answer (if submitted)
submission_file_urlAbsolute URL to uploaded file
submitted_atTimestamp of submission
marks_obtainedScore given by teacher (nullable)
feedbackTeacher feedback text

6. Dashboard APIs
GET /api/dashboard/ Auth Required

View Class: DashboardView — Method: get(request)

Aggregates all student dashboard data in a single request. Queries all user enrollments and computes stats in-memory. Returns user profile, stats summary, a "Continue Learning" item (most recent incomplete enrollment), and the last 5 recent enrollments.

Response FieldDescription
userCurrent user profile (UserProfileSerializer)
stats.active_coursesCount of ongoing (not completed) enrollments
stats.completed_coursesCount of fully completed enrollments
stats.total_enrollmentsTotal enrollment count
stats.average_progressRounded mean progress % across all enrollments
continue_learningMost recent incomplete enrollment (for Resume button)
recent_enrollmentsLast 5 enrollments with course info
GET /api/teacher/courses/ Teacher Only

View Class: TeacherCourseListView

Returns all courses where the instructor is the currently logged-in teacher. Restricted by IsTeacher permission class. Uses the same CourseListSerializer as the public course list.

GET /api/teacher/students/ Teacher Only

View Class: TeacherStudentListView — Method: get(request)

Returns all students enrolled in any of the teacher's courses. Queries courses by teacher → then all enrollments for those courses. Builds and returns a custom list (not a serializer).

Response Field (per item)Description
enrollment_idID of the enrollment record
student_nameFull name of the student
student_emailStudent's email address
course_titleName of the enrolled course
progressStudent's progress percentage
enrolled_atEnrollment timestamp
GET /api/admin/dashboard/ Admin Only

View Class: AdminDashboardView — Method: get(request)

Returns platform-wide statistics. Revenue is computed with Django's aggregate(Sum('amount')) across all Payment records. Restricted by IsAdmin permission class.

Response FieldDescription
total_coursesTotal number of courses in the system
total_studentsUser count with role='student'
total_teachersUser count with role='teacher'
total_revenueSum of all Payment.amount values

7. Contact API
POST /api/contact/ Public

View Class: ContactView

Saves a contact form submission to the database as a ContactMessage record. Fully public — no authentication required. CSRF is disabled via @csrf_exempt so the static HTML frontend can call it directly. Returns HTTP 201 on success. Admins can view and mark messages as read in the Django admin panel.

Request FieldRequiredDescription
nameYesSender's name
emailYesSender's email address
phoneOptionalPhone number
subjectOptionalMessage subject line
messageYesFull message body

9. Serializers

Serializers in api/serializers.py control how model instances are converted to/from JSON and handle input validation on write operations.

UserRegistrationSerializer

Handles new user sign-up. Validates password strength via Django's built-in validators, checks email uniqueness, splits full_name into first/last, auto-generates a unique username from the email prefix, and calls create_user().

UserProfileSerializer

Read-only profile data returned after login/register and by /me/. Adds two computed fields: full_name (calls get_full_name()) and avatar_initial (first letter of name, upper-cased — used for avatar circle in the UI).

UserUpdateSerializer

Allows updating: first_name, last_name, phone, bio, profile_picture. Used with partial=True so individual fields can be updated without sending the entire profile.

CategorySerializer

Adds a computed course_count field counting only active courses in that category (filters is_active=True). Returns: id, name, slug, icon, description, course_count.

CourseListSerializer

Lightweight serializer for course listing cards. Adds: category_name, category_slug, instructor_name (from related User model), and an absolute thumbnail_url (built from request context). Includes is_enrolled field (defaults False; annotated by views for authenticated users).

CourseDetailSerializer (extends CourseListSerializer)

Adds extra fields for the course detail page: description, created_at, outline (JSON array), roadmap (JSON array), assignments_count, exams_count, quizzes_count.

CoursePlayerSerializer (extends CourseDetailSerializer)

The heaviest serializer — adds fully nested modules (each module contains its videos, resources, and assignments via ModuleSerializer). Used only by the course player view to provide all course content in one API call.

EnrollmentSerializer

Nests the full CourseListSerializer for read operations. For write operations, accepts a course_id field. The create() override uses get_or_create to safely handle duplicate enrollment attempts (idempotent).

ModuleSerializer

Includes nested VideoSerializer (all videos in the module), ResourceSerializer (all resources), and a custom get_assignments() method returning all assignments via AssignmentSerializer. Provides the full content tree for one module.

StudentAssignmentSerializer

Adds read-only computed fields: assignment_title and student_name. The marks_obtained and feedback fields are read-only — they can only be set by admins/teachers via the Django admin panel.

PaymentSerializer

Adds read-only course_title and user_name fields for display. Timestamps (created_at) and status are also read-only.

ContactMessageSerializer

Simple serializer for the contact form. The submitted_at field is read-only and auto-set by the model. Used in the public ContactView API.

10. Custom Permissions

Three custom permission classes in api/permissions.py extend DRF's BasePermission. They inspect the role field on the User model.

IsAdmin
Grants access if user.role == 'admin' or user.is_superuser.
Used on: /api/admin/dashboard/
IsTeacher
Grants access if role is 'teacher' or 'admin' (admins can access teacher views too).
Used on: /api/teacher/courses/ and /api/teacher/students/
IsStudent
Grants access to any authenticated user (student, teacher, or admin). Defined and available but not currently applied to a specific route.
